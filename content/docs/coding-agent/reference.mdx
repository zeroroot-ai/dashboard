## Environment variables

| Variable | Default | What it does |
|---|---|---|
| `GIBSON_PLATFORM_URL` | none | The platform endpoint. Without it the plugin stays standalone. |
| `GIBSON_BOOTSTRAP_TOKEN` | none | The one-time enrollment token. Read only on the first start, and ignored once a host key exists. |
| `GIBSON_HOST_KEY_PATH` | `~/.zerocool/host.key` | Where the host key is written and read. |
| `GIBSON_DAEMON_URL` | discovered | Overrides the daemon endpoint. |
| `GIBSON_AGENT_MODE` | `autonomous` | The agent mode reported at registration. |
| `GIBSON_SHIM_PORT` | `8787` | The port of the local OpenAI-compatible endpoint. Change it if the port is taken. |
| `ZEROCOOL_AMBIENT_QUERY` | prior findings and security facts for this codebase | The knowledge query injected into the system prompt. |
| `ZEROCOOL_FINDINGS_LOG` | `~/.zerocool/findings.jsonl` | Where standalone findings are written. |

## Files on disk

| Path | What it is |
|---|---|
| `~/.zerocool/host.key` | The persistent identity of this install. Its presence is what makes a start unattended. |
| `~/.zerocool/findings.jsonl` | Standalone findings log. Only written when the platform is not reachable. |
| `.opencode/plugin/zerocool.ts` | The project-level plugin entry point. |
| `~/.config/opencode/plugin/zerocool.ts` | The same, for every project. |

Delete the host key to force a fresh enrollment. You then need a new
bootstrap token: the old one was spent.

## Optional plugins

Install these next to the main plugin. They share its Gibson session, so
they add no second sign-in.

### `@zerocool/opencode-gibson-exec`

Routes execution into a setec Devbox instead of your workstation, using
opencode's remote-workspace protocol. Untrusted code then runs in a
microVM, not on your machine.

This is invasive: it changes where your commands run. Adopt it
deliberately.

### `@zerocool/opencode-gibson-sessions`

Mirrors local session context into the daemon store, so a session
survives the workstation. It changes where your state lives, so it is
also opt-in.

## Troubleshooting

### "GIBSON_PLATFORM_URL is set but this host has not checked in"

The plugin found a platform URL, no host key, and no usable bootstrap
token. Either the token was not in the environment, or the variable name
was wrong. Check the spelling of `GIBSON_BOOTSTRAP_TOKEN`, then repeat
[step 4](/docs/coding-agent/setup).

If the token expired, mint another with `gibson agent enroll --name
zerocool`. Tokens live 24 hours.

### "Gibson connect failed; continuing standalone"

The plugin reached the check-in and it failed. The message carries the
reason. Common causes:

1. **Your membership is not active.** Enrollment authorizes against your
   tenant membership. Accept the invitation in the dashboard first.
2. **The platform URL is wrong or unreachable.** Confirm it with
   `gibson inspect` against the same URL.
3. **The token was already spent.** A bootstrap token is consumed by one
   check-in. Mint a new one.

opencode keeps working through all of these, in standalone mode.

### A tool reports "unavailable"

A tool answers with an unavailable note when the platform seam behind it
is not enabled for your deployment. It is not an error in your session,
and it does not stop the agent. Ask your operator which capabilities
your tenant has.

### The model list has no `gibson/` entries

The provider is registered at config-load time, and only when check-in
succeeds. If check-in fell back to standalone, no provider appears. Read
the `[zerocool]` lines on stderr first. They say which mode the session
is in.

### Port 8787 is in use

Set `GIBSON_SHIM_PORT` to a free port. The provider follows the shim
automatically.
